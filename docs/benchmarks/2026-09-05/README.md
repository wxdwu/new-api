# 2026-09-05 稳定性对照实验原始证据

本目录保存隔离环境中的脱敏 HTTP Responses 流式请求样本、模拟上游尝试、环境信息和分析工具；不包含账户凭据、原数据库或真实用户请求。结论见 ../../stability-benchmark-results.zh_CN.md。

## 文件说明

- `results/experiment-index.json`：完整轮次、执行顺序、配置、发流与排空时间、容器状态。
- `results/*.client.json`：逐条计划发送/实际发送/结束时间、完整响应判定、HTTP 状态、首段和完成耗时。
- `results/*.upstream.json`：逐次上游渠道、返回状态、在途量、模拟容量及故障配置。
- `results/environment.json`：实际镜像 ID、资源配额与实验边界。
- `results/container-stats.jsonl`：Docker 连续资源快照，已去除终端控制字符；原始输出另存 `.raw`。没有逐行时间戳，不能按实验臂计算资源降幅，采样峰值也不是精确上界。
- `results/summary.json`、`results/per-run.csv`：由保存的请求样本重新计算的汇总。
- `tools/`：本次实际测试和分析工具；路径及私网地址针对本次临时环境。工具内没有真实密钥。

## 复核与重做

在本目录执行 `python3 tools/analyze.py results` 可重新检查请求关联、次数和容量约束，并产生汇总。工具契约测试：进入 tools 后执行 `python3 -m unittest -v test_benchmark.py`；需要允许监听本机回环地址。

重做服务实验需要先建立相同镜像、独立数据库/Redis/Nginx和 Docker 内部网络，生成仅用于临时环境的管理员及 API Token，再调整工具中的私网地址。正式运行使用 `python3 -u run_experiments.py`。已有实验索引会阻止覆盖结果，应为新实验创建新目录。环境已在测试完成后清理，脚本不是可直接对原服务执行的上线工具。

## 指标边界

成功要求收到有效文本和 `response.completed`，HTTP 200 单独不算成功；超时、拒绝、流中断均计失败。客户端不重试，重试只能发生在网关。

本实验没有实际 Agent 工具调用、真实模型供应商、生产失败率基线或旧版程序对照；两组始终使用同一网关镜像，仅改变明确的配置。上游容量和故障都是人为注入，不应将这里的数字写成生产可用性、机器容量上限或个人从零实现调度算法的证据。

P95 仅统计完整成功的请求，并同时披露失败率，避免把快速拒绝解释为低延迟。每组 3 个短窗口不能证明长期可靠性。故障窗口使结果相关，汇总中的二项区间仅为描述性数据，不用它推断生产置信区间。
